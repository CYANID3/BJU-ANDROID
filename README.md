# БЖУ — Android / Capacitor

Дневник питания (калории, белки, жиры, углеводы). Веб-интерфейс из `index.html`, обёрнутый в Android-приложение через Capacitor.

## Структура
- `index.html` — разметка страницы. Стили и логика лежат по частям в `src/`:
  - Оформление: без рамок — глубину задают тона (фон → карточка → блок), рамки только у полей ввода. Шрифт — Manrope (пакет `@fontsource-variable/manrope`, встроен в приложение, работает без сети).
  - `src/css/00-base.css` — **единая система размеров** (скругления, высоты полей и кнопок, шрифты): все элементы берут значения оттуда, поэтому кнопки, поля, сегменты и списки везде одинаковые. Поменять, например, скругление всех полей и кнопок — одна строка;
  - `src/css/NN-*.css` — стили по разделам (палитра, шапка, карточки, нижний лист, календарь, статистика…);
  - `src/js/NN-*.js` — логика по разделам (данные, хранение, формат файла, главный экран, статистика, карточка дня, список продуктов, календарь, жесты, клавиатура, настройки, вес…).
  При сборке (и в `npm run dev`) Vite склеивает части по порядку номеров в один `<style>` и один обычный `<script>` прямо в странице — поведение такое же, как у одного файла: общие переменные и `onclick="…"` работают без импортов. Новую часть достаточно положить в папку с нужным номером.
- `tests/` — автотесты (Playwright, Chromium в эмуляции Pixel 7).
- `capacitor-bridge.js` — связь страницы с Android: файлы, вибрация, кнопка «Назад», системные отступы и клавиатура.
- `native/android/` — собственный нативный код (Java), копируется в проект при сборке:
  - `BjuNativePlugin.java` — системный выбор файла с постоянным доступом (SAF), отступы статус-бара/навигации/клавиатуры, цвет системных панелей;
  - `BjuWidget.java` — виджет рабочего стола;
  - `MainActivity.java` — регистрирует плагин;
  - `res/` — разметка виджета, ярлыки быстрых действий, иконки и строки (всё с префиксом `bju_`).
- `scripts/icon-svg.mjs` — **исходник иконки приложения**: минималистичное кольцо из трёх дуг Б / Ж / У (как кольцо на карточке дня), рисуется кодом. Три варианта оформления: `dark` (по умолчанию), `light`, `accent` — выбирается полем `"icon"` в `package.json`. `npm run icons` (`scripts/icons.mjs`) делает из него все иконки: favicon, PWA, иконку Android (адаптивную — лаунчер сам задаёт форму), splash **заставку при запуске** (кольцо без фона в `res/drawable-nodpi/bju_splash_logo.png`: `bju_splash` ставит его по центру фиксированного размера на фоне иконки, а `patch-android.mjs` подключает эту заставку вместо растягиваемой `splash.png` и задаёт тот же значок и фон системной заставке Android 12+; кольцо не растягивается ни на каком экране) и и **монохромный слой для «тематических значков» Android 13+**: если в настройках обоев включены тематические значки, иконка перекрашивается в цвета обоев и темы (светлой/тёмной).
- `scripts/shortcut-icons.py` — значки ярлыков (Завтрак, Обед, Ужин, Перекус, Вес): мягкий цветной фон и линейный символ, на Android 8+ — адаптивные.
- `public/` — файлы, которые копируются в сборку как есть (manifest, service worker, иконки).
- `scripts/patch-android.mjs` — донастройка Android-проекта: номер версии, нативный код, режим клавиатуры, портретная ориентация.
- `keystore/debug.keystore` — постоянный ключ подписи APK (см. ниже).

## Сборка через GitHub
Каждый push в `main` (или ручной запуск: **Actions → Build Android APK → Run workflow**):
1. собирает APK;
2. создаёт **релиз** `v1.0.N` (N — номер запуска) с файлом `BJU-1.0.N.apk` — его можно скачать прямо со страницы **Releases** на телефоне;
3. дополнительно кладёт APK в артефакты запуска (хранятся 14 дней).

Версию `1.0` можно поменять в `package.json` (поле `version`, используются первые две цифры).

## Подпись и обновления
Android разрешает обновить приложение только APK, подписанным тем же ключом. Раньше каждая сборка на GitHub подписывалась новым случайным ключом, поэтому приходилось удалять приложение (и терять данные).

Теперь используется постоянный ключ `keystore/debug.keystore`, и новые версии ставятся поверх старых.
**Один раз** (переход со старых сборок) приложение всё же придётся переустановить: перед этим сохраните копию данных через «Файл» и после установки откройте её.

Если репозиторий публичный и хочется собственный секретный ключ — добавьте в *Settings → Secrets → Actions*:
`ANDROID_KEYSTORE_BASE64` (keystore в base64), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Тогда workflow соберёт release-APK с этим ключом (смена ключа — снова одна переустановка).

## Где хранятся данные
- Внутри приложения (`localStorage` + файл в приватной папке) — всегда.
- **Основной файл** — выбирается в «Файл»: «Создать файл данных» или «Открыть существующий файл» (системный диалог Android, можно выбрать любую папку, в т.ч. облачную). Приложение получает постоянный доступ к файлу: он остаётся основным после перезапуска и обновлений, а все изменения сохраняются в него автоматически.
- При запуске берётся самая свежая копия (например, если файл обновился с другого устройства).
- Если доступ к файлу пропал (файл удалён/перемещён), на главном экране появится предупреждение с кнопкой «Выбрать».
- Данные из `Documents/BJU/bju-data.json` старых версий подхватываются автоматически при первом запуске.

## Потянуть вверх — откуда
Настройки → Жесты → «Откуда тянуть» (под «Потянуть вверх в конце дня», `src/js/21-pull.js`):
- **«От панели»** (если нижняя панель закреплена) — потянуть вверх от панели в любом месте списка; кнопки панели при этом не нажимаются, обычное касание — как раньше;
- **«От низа экрана»** (если не закреплена) — потянуть вверх из полоски ~32 px над системной полоской Android (с самого края свайп забирает система). Срабатывает только при вытягивании до порога; быстрый мах оттуда — это прокрутка, а не жест;
- **«В конце списка»** — только как раньше. Тянуть в конце списка можно при любом выборе.
По умолчанию — от панели / от низа экрана. В файле: `pullUpFrom`: edge/listEnd.

## Подсказки к жестам
Переключатель «Показывать подсказки» во вкладке «Жесты» показывает и скрывает (плавно) мини-телефоны с анимацией под каждым включённым жестом: палец тянет список вниз или вверх. По умолчанию скрыты; выбор хранится в настройках файла (`gestureHints`).

## Слияние баз продуктов
«Файл» → «Добавить продукты из другого файла»: из чужого файла (например, файла другого человека) берутся только продукты и блюда, дневник и настройки не меняются (`src/js/28-merge.js`):
1. **тот же продукт** — тот же набор слов в названии: регистр, «ё», пробелы, знаки и порядок слов не важны («Грудка куриная» = «Куриная грудка», «творог 5 %» = «Творог 5%»). Склеивается сам: остаётся ваш, к нему добавляются недостающие меры (банка, штука…);
2. **похожие** — одно название входит в другое (или большая часть слов общая) и БЖУ близкое: её «Яйцо» и ваше «Яйцо (варёное)». Такие пары собираются на экране «Похожие продукты» (для каждого — ваш самый близкий по БЖУ) с выбором «Разные» / «Это одно»; по умолчанию «Разные», так что «Готово» без выбора ничего не склеит. Пока не нажато «Готово», список не меняется; «Назад» отменяет импорт;
3. **новые** — добавляются в конец списка.

Разные числа в названии («Молоко 2,5%» и «Молоко 3,2%»), продукт и блюдо — всегда разные. В тосте — сколько добавлено и сколько новых мер, «Отменить» возвращает прежний список. Кнопку можно убрать: Настройки → Данные → «Импорт продуктов из файла».

## Автотесты
`npm run test:all` — сборка и все тесты; `npm test` — только тесты по уже собранной `www/`. Проверяются: добавление и удаление записей, норма, свайп дней, календарь, смахивание листа, «Назад», клавиатура, настройки, нижняя панель, избранное и недавние, блюда в списке, расположение панели и кнопок, вес, статистика, карточка дня, формат файла и понятные ошибки, основной файл в APK (на моке нативной части), виджет и ярлыки.
На GitHub тесты запускаются перед сборкой APK: если хоть один упал, APK не собирается и релиз не создаётся (ошибка видна в журнале шага **Run tests**). Локально нужен Chromium: `npx playwright install chromium` (или путь в `CHROMIUM_PATH`).

## Расположение (Настройки → Расположение)
- **Нижняя панель** (Норма, Продукты, Статистика, Файл, Настройки): «В конце дня» (по умолчанию) — после приёмов пищи; «Всегда видна» — закреплена у нижнего края экрана: свой, чуть более светлый тон с тонким контуром и тенью, а страница под ней плавно затемняется, поэтому длинный список не сливается с панелью; тосты и индикатор жеста «потянуть вверх» поднимаются над ней, на карточке дня панель скрыта.
- **Кнопки «Новый продукт» и «Новое блюдо»**: «Под списком» (как раньше) или «Под поиском». Действует во всех списках продуктов: при добавлении в приём пищи, в «Продуктах» и при выборе ингредиента для блюда.

## Избранное и недавние
В списке продуктов у каждого есть звёздочка. При добавлении без поиска список делится на разделы: **Избранное**, **Недавние** (последние добавленные, до 8) и **Все продукты** (по частоте). При поиске избранные идут первыми. Блюда отмечены значком-миской и подписью «Блюдо»; в «Продуктах», если есть хотя бы одно блюдо, сверху есть фильтр «Все / Продукты / Блюда».

## Главный экран
Сверху — итог дня: калории, полоса калорий, разделённая по цветам на вклад белков, жиров и углеводов (сразу видно и сколько съедено, и из чего; перебор — красная обводка), остаток, под ними три плитки Б / Ж / У (съедено / норма, полоска, сколько ещё и доля калорий). Ниже — две плитки: **Вес** (касание — записать или изменить) и **В среднем за 7 дней** (касание — статистика). Затем приёмы пищи: каждая запись — отдельная строка-плашка. Пустые перекусы (Настройки → Главный экран): «Тонкой строкой» — строка «＋ Перекус N» между приёмами; «По двойному касанию» — пустых не видно, два касания по названию основного приёма (например, «Обед») выдвигают под ним «＋ Перекус 2», ещё два — убирают; пустой выдвинутый перекус сам прячется при смене дня. С записями перекус — обычная карточка.

Настройки — четыре вкладки (закреплены сверху листа; листаются и пальцем вбок; лист всегда в полную высоту, так что при смене вкладки не прыгает; открываются там, где были в прошлый раз): **Вид** (тема, акцент и «Свой цвет», оттенок фона), **Экран** (нижняя панель «В конце дня / Всегда видна», кнопки «Новый продукт» и «Новое блюдо» «Под списком / Под поиском», пустые перекусы, «Отслеживать вес»), **Жесты** (каждый жест — своя группа: действие, у «Потянуть вверх» ещё «Откуда тянуть», анимированная подсказка; длина свайпа; «Показывать подсказки»), **Прочее** (вибрация, «Импорт продуктов из файла»). Выбор из 2–3 вариантов — сегментом с понятными подписями, из 4 и больше — списком, свёрнутым до выбранного; переключатели — только для «да / нет»; под неочевидными пунктами — короткое пояснение. В тёмной теме три ступени глубины: фон → карточка → блок внутри карточки.

## Цвета и анимации

Цвета, производные от акцента, считаются под текущую тему и оттенок фона: значки и текст акцентом (`--act`) осветляются в тёмной теме и затемняются в светлой, пока контраст на мягкой подложке не достигнет 4,5 : 1 на любом фоне (карточка, блок, нижняя панель). Текст на заливке акцентом (`--on`) — белый или тёмный, в зависимости от того, что читается лучше. Поэтому значки не тускнеют ни с серым, ни с фиолетовым, ни с жёлтым акцентом. В переключателях (тема, вибрация, граммы / штуки…) выбранный вариант отмечен «таблеткой» акцентного цвета, которая плавно переезжает к нажатому; остальные варианты — просто текст на подложке.

У всех анимаций одни кривые и длительности: в CSS это `--ease`, `--spring` и `--t1`…`--t3` (0,16 / 0,26 / 0,36 с), в JS — `MO` в `src/js/05a-motion.js`. Перекус, открытый двойным касанием, плавно выезжает под приёмом и так же уезжает, раздвигая и сдвигая соседние карточки. Список на главном экране перестраивается плавно: карточки и записи переезжают на новое место, новые записи проявляются, удалённая тает там, где была. Диалоги и нижний лист появляются и скрываются с затуханием фона. При системной настройке «Уменьшить движение» анимации выключены. Основная кривая мягкая: плавный старт и долгое торможение — даже если первые кадры на слабом телефоне запаздывают, рывка не видно. Для плавности на слабых устройствах: нижняя панель без размытия фона (под почти непрозрачной панелью его не видно, а считается оно на каждом кадре прокрутки); главный экран выносится в отдельный слой только на время перетаскивания; строки списка продуктов за краем экрана не отрисовываются (`content-visibility`), а сам список показывает первый экран сразу, остальное — когда браузер свободен.

Добавление: в списке продуктов и на экране количества сверху выбор приёма пищи — сетка 3×2 (в столбце основной приём и перекус после него). Жест, ярлык и «＋» виджета подставляют приём по времени, а здесь его можно сменить одним касанием. После «Добавить» лист возвращается в список того же приёма, так что следующий продукт добавляется в одно касание, а в тосте можно отменить добавление. При изменении записи (двойное касание) выбора приёма нет: меняются только количество и мера, после «Сохранить» лист закрывается. «Длина свайпа» в настройках — ползунок на три положения: бегунок можно перетащить или выбрать подпись. Поля количества и веса открываются в «режиме замены»: значение не выделяется как текст — подсвечено всё поле (мягкая заливка акцентом, значение акцентом, без курсора), а первая набранная цифра заменяет значение целиком («Стереть» очищает поле). То же после касания быстрого значения или кнопок ±0,1 кг. Касание самого поля выходит из режима: значение выделяется как обычно, дальше курсор стандартный. Курсор и выделение в полях — в цвет акцента.

**Свой цвет** (Настройки → Оформление): вместо системного окна выбора открывается свой экран в листе. Там квадрат насыщенности и яркости, полоса оттенка, поле для кода `#RRGGBB` и десять готовых оттенков; кнопка «Готово» сразу окрашена в выбранный цвет. «Назад» возвращает в настройки без изменений. В строке «Свой цвет» виден текущий цвет и его код.

## Вес
**Статистика за месяц** (свайп — соседний месяц): сверху «В среднем за день» в том же виде, что итог дня на главном экране (калории, полоса по вкладу Б / Ж / У, три плитки). Под ним три цифры: дни с записями, дни в норме ±10%, лучшая серия. Ниже «Калории по дням»: каждый столбец сложен из вклада белков, жиров и углеводов, пунктиром отмечена норма. Затем вес, «БЖУ по дням» в процентах от нормы и «Чаще всего»: пять продуктов строками, с числом записей и средней калорийностью за раз. Касание графика показывает данные дня.

Плитка «Вес» под итогом дня: «72,4 кг» и разница с прошлой записью, если вес за этот день записан, и «Записать» (с прошлым весом мелко), если нет. Касание открывает ввод (кнопки ±0,1 кг, рядом — прошлая запись и разница). Если в «Потянуть вверх» выбран «Вес», вес записывается жестом, а кнопка «+ вес» скрыта. Одна запись на день. В статистике под графиком калорий — линия веса за месяц с изменением за месяц. Если в этот день записан вес, он есть и на карточке дня (плашка под остатком калорий). Отключается в **Настройки → Вес** (записи при этом сохраняются).

## Статистика за месяц
Кнопка «Статистика» в центре нижней панели. Месяц переключается стрелками или свайпом в стороны. Показывает: дни с записями, средние калории и % нормы, дни в норме (±10%), самую длинную серию; график калорий по дням с линией нормы; БЖУ по дням в % от нормы (три линии: сплошная, пунктир, точки); средние БЖУ за день и доли калорий; продукты, которые записывались чаще всего. Касание графика показывает значения дня.

## Карточка дня
Тройное касание по итогу дня открывает **карточку дня** — сводку для скриншота (например, тренеру): дата, калории и остаток, кольцо долей Б/Ж/У, вес за день, плитки Б / Ж / У (как на главном экране) и все приёмы пищи одним блоком. Продукты — ровные строки с колонками «название · количество · ккал». **Компактный вид** (свайп вверх) — те же колонки плотнее, всё помещается на один экран (при необходимости карточка целиком чуть уменьшается); **подробный** (свайп вниз) — у каждого приёма полоса его состава (вклад Б / Ж / У в калории приёма) и доля от нормы дня, у приёмов и продуктов — БЖУ цветными буквами. Кольцо долей Б/Ж/У — с чёткими границами и ровными зазорами. По умолчанию открывается компактный вид. Дни листаются свайпом в стороны; выход — тройное касание или «Назад».

## Виджет и быстрые действия
- **Виджет** «БЖУ за сегодня» (долгое нажатие на рабочем столе → Виджеты), размер от 1×1 до 4×2 (если лаунчер не соблюдает предел и позволяет растянуть выше, включаются увеличенные раскладки). Раскладки генерирует `scripts/widget-layouts.py`. Восемь основных раскладок под размер: 1×1 — Б/Ж/У съедено; 2×1 — колонки с полосками; 3×1 и 4×1 — «съедено/норма» (на 4×1 ещё «+»); 1×2 — блоки со «из нормы»; 2×2 — остаток калорий и строки БЖУ; 3×2 — калории, «+» и колонки с остатком; высокий 4×2 — калории с полосой и подробные строки. Цвета, тема и оттенок фона — как в приложении; после полуночи виджет сам показывает новый пустой день. В списке виджетов (Android 12+) показано тёмное превью с правдоподобным днём (1146 из 2110 ккал, Б / Ж / У с полосками); до первого обновления виджет тоже тёмный и с верными подписями. Разметки генерирует `scripts/widget-layouts.py`.
- **Быстрые действия** — долгое нажатие на иконку приложения: Завтрак, Обед, Ужин, Перекус (ближайший по времени) и **Вес** (только если отслеживание веса включено; если выключить, закреплённый ярлык «Вес» становится неактивным). Сразу открывается добавление в выбранный приём пищи или ввод веса на сегодня.
- Оба механизма открывают ссылку `bju://add?m=…` (`0`–`5` — номер приёма пищи, `snack` — ближайший перекус, `auto` — по времени); ярлык веса — `bju://weight`.

## Формат файла данных (версия 3)
Файл — обычный JSON с отступами, его можно править вручную в любом текстовом редакторе.

```json
{
  "format": "bju-diary",
  "version": 3,
  "savedAt": "2026-10-16T11:00:00.000Z",
  "goals": { "protein": 120, "fat": 70, "carbs": 250 },
  "products": [
    { "name": "Творог 5%", "per100g": { "protein": 17, "fat": 5, "carbs": 1.8 }, "favorite": true },
    { "name": "Куриная грудка (сырая)", "per100g": { "protein": 23.6, "fat": 1.9, "carbs": 0.4 },
      "units": [ { "name": "шт", "grams": 180 } ] },
    { "name": "Салат", "per100g": { "protein": 2, "fat": 5, "carbs": 6 },
      "dish": { "cookedWeight": 300, "ingredients": [
        { "name": "Огурец", "grams": 200, "protein": 1.6, "fat": 0.2, "carbs": 5 } ] } }
  ],
  "diary": {
    "2026-10-16": {
      "breakfast": [ { "name": "Яблоко", "grams": 55, "protein": 0.2, "fat": 0.2, "carbs": 5.4,
                       "unit": { "name": "шт", "count": 1 } } ],
      "lunch": [ { "name": "Рис", "grams": 100, "protein": 7, "fat": 1, "carbs": 74 } ]
    }
  },
  "weight": { "2026-10-16": 72.4 },
  "settings": { "theme": "dark", "accentColor": "#22a06b", "pullUpAction": "meal",
                "pullDownAction": "calendar", "vibration": "on", "swipeLength": "medium",
                "backgroundTint": "soft", "weightTracking": "on",
                "bottomBar": "page", "newButtons": "bottom" },
  "stats": { "useCount": { "Рис": 3 }, "lastGrams": { "Рис": 100 }, "recent": [ "Рис" ] }
}
```

| Раздел | Что это |
|---|---|
| `goals` | Норма на день, граммы белков / жиров / углеводов (калории считаются: Б×4 + Ж×9 + У×4) |
| `products` | Список продуктов. `per100g` — БЖУ на 100 г (незаполненное считается 0). `units` — свои единицы («шт» = 180 г), необязательно. `dish` — только у блюд: вес готового блюда и ингредиенты. `favorite: true` — в избранном |
| `diary` | Дневник по датам `ГГГГ-ММ-ДД`. Приёмы пищи: `breakfast`, `snack1`, `lunch`, `snack2`, `dinner`, `snack3` (пустые можно не писать). В записи — масса порции `grams` и БЖУ **этой порции**; `unit` — если добавляли в штуках |
| `weight` | Вес по дням, кг (одна запись на день) |
| `settings` | `theme`: auto/light/dark; `accentColor`: цвет `#rrggbb`; `pullUpAction`: meal/product/stats/weight/off; `pullDownAction`: calendar/today/off; `vibration`: on/exceptDays/off; `swipeLength`: short/medium/long; `backgroundTint`: off/soft/strong — примесь акцентного цвета в фон; `weightTracking`: on/off; `bottomBar`: page/fixed; `newButtons`: bottom/top; `snacks`: row/doubleTap; `productImport`: on/off — кнопка «Добавить продукты из другого файла»; `gestureHints`: on/off — подсказки к жестам; `pullUpFrom`: edge/listEnd — откуда тянуть вверх|
| `stats` | Служебное: сколько раз продукт добавлялся (сортировка списка), последняя масса (подсказка) и недавние продукты. Можно удалить |

Если при открытии файла что-то не так, приложение покажет, где именно ошибка: например, «день 2026-10-01: неизвестный приём пищи «lanch»» или «продукт №5: нет названия». Файлы старого формата тоже открываются и при следующем сохранении записываются в новом.

## Локальная сборка
```bash
npm ci
npm run android:prepare   # иконки + веб-сборка + android/ + версия
cd android && ./gradlew assembleDebug
```
Папки `android/`, `www/`, `assets/` генерируются и в репозиторий не коммитятся.
