# БЖУ — Android / Capacitor

Дневник питания (калории, белки, жиры, углеводы). Веб-интерфейс из `index.html`, обёрнутый в Android-приложение через Capacitor.

## Структура
- `index.html` — разметка страницы. Стили и логика лежат по частям в `src/`:
  - Оформление: без рамок — глубину задают тона (фон → карточка → блок), активное поле подсвечивается контуром акцента. Шрифт — Manrope (пакет `@fontsource-variable/manrope`, встроен в приложение, работает без сети).
  - `src/css/00-base.css` — **единая система размеров** (скругления, высоты полей и кнопок, шрифты): все элементы берут значения оттуда, поэтому кнопки, поля, сегменты и списки везде одинаковые. Поменять, например, скругление всех полей и кнопок — одна строка;
  - `src/css/NN-*.css` — стили по разделам (палитра, шапка, карточки, нижний лист, календарь, статистика…);
  - `src/js/NN-*.js` — логика по разделам (данные, хранение, формат файла, главный экран, статистика, карточка дня, список продуктов, календарь, жесты, клавиатура, настройки, вес…).
  При сборке (и в `npm run dev`) Vite склеивает части по порядку номеров в один `<style>` и один обычный `<script>` прямо в странице — поведение такое же, как у одного файла: общие переменные и `onclick="…"` работают без импортов. Новую часть достаточно положить в папку с нужным номером.
- `tests/` — автотесты (Playwright, Chromium в эмуляции Pixel 7).
- `capacitor-bridge.js` — связь страницы с Android: файлы, вибрация, кнопка «Назад», системные отступы и клавиатура.
- `native/android/` — собственный нативный код (Java), копируется в проект при сборке:
  - `BjuNativePlugin.java` — системный выбор файла с постоянным доступом (SAF), отступы статус-бара/навигации/клавиатуры, цвет системных панелей, системные виброотклики (`feedback`);
  - `BjuWidget.java` — виджет рабочего стола;
  - `MainActivity.java` — регистрирует плагин;
  - `res/` — разметка виджета, ярлыки быстрых действий, иконки и строки (всё с префиксом `bju_`).
- `scripts/icon-svg.mjs` — **исходник иконки приложения**: три кольца-шкалы Б / Ж / У (зелёное, жёлтое, синее — цвета нутриентов на экранах; каждое — «съедено из нормы», как кольца прогресса в приложениях здоровья), рисуется кодом. Три варианта: `dark` (графит; выбран), `accent` (индиго), `light` — поле `"icon"` в `package.json`. Адаптивная иконка Android 8+ — **векторные слои** `res/drawable/bju_ic_fg.xml`, `bju_ic_bg.xml`, `bju_ic_mono.xml` (чёткие на любой плотности; `patch-android.mjs` пишет их в `mipmap-anydpi-v26/ic_launcher*.xml` вместо картинок @capacitor/assets, которые лаунчер растягивал в 1,5 раза, и удаляет векторы шаблона Capacitor); картинки `mipmap-*/ic_launcher*.png` остаются для Android 6–7. `npm run icons` (`scripts/icons.mjs`) делает из него все иконки: favicon, PWA, иконку Android (адаптивную — лаунчер сам задаёт форму), splash **заставку при запуске** (кольца без фона в `res/drawable-nodpi/bju_splash_logo.png`: `bju_splash` ставит его по центру фиксированного размера на фоне иконки, а `patch-android.mjs` подключает эту заставку вместо растягиваемой `splash.png` и задаёт тот же значок и фон системной заставке Android 12+; значок не растягивается ни на каком экране) и и **монохромный слой для «тематических значков» Android 13+**: если в настройках обоев включены тематические значки, иконка перекрашивается в цвета обоев и темы (светлой/тёмной).
- `scripts/shortcut-icons.py` — значки ярлыков (Завтрак, Обед, Ужин, Перекус, Вес): мягкий цветной фон и линейный символ, на Android 8+ — адаптивные.
- `public/` — файлы, которые копируются в сборку как есть (manifest, service worker, иконки).
- `scripts/patch-android.mjs` — донастройка Android-проекта: номер версии, нативный код, режим клавиатуры, портретная ориентация.
- `keystore/debug.keystore` — постоянный ключ подписи APK (см. ниже).

## Сборка через GitHub
Каждый push в `main` (или ручной запуск: **Actions → Build Android APK → Run workflow**):
1. собирает APK;
2. создаёт **релиз** `v1.0.N` (N — номер запуска) с файлом `BJU-1.0.N.apk` — его можно скачать прямо со страницы **Releases** на телефоне;
3. дополнительно кладёт APK в артефакты запуска (хранятся 14 дней).

Версию `1.0` можно поменять в `package.json` (поле `version`, используются первые две цифры).

## Подпись и обновления
Android разрешает обновить приложение только APK, подписанным тем же ключом. Раньше каждая сборка на GitHub подписывалась новым случайным ключом, поэтому приходилось удалять приложение (и терять данные).

Теперь используется постоянный ключ `keystore/debug.keystore`, и новые версии ставятся поверх старых.
**Один раз** (переход со старых сборок) приложение всё же придётся переустановить: перед этим сохраните копию данных через «Файл» и после установки откройте её.

Если репозиторий публичный и хочется собственный секретный ключ — добавьте в *Settings → Secrets → Actions*:
`ANDROID_KEYSTORE_BASE64` (keystore в base64), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Тогда workflow соберёт release-APK с этим ключом (смена ключа — снова одна переустановка).

## Где хранятся данные
Копия в памяти браузера (`localStorage`) после правки пишется не в кадре нажатия, а когда отыграют его анимации (`storeSoon()` в `src/js/01-data.js`: через 0,38 с в свободное время браузера, не позже 0,8 с; серия правок — одна запись; при сворачивании приложения — немедленно): за год записей это ~250 КБ, и запись больше не задерживает отклик.
- Внутри приложения (`localStorage` + файл в приватной папке) — всегда.
- **Основной файл** — выбирается в «Файл»: «Создать файл данных» или «Открыть существующий файл» (системный диалог Android, можно выбрать любую папку, в т.ч. облачную). Приложение получает постоянный доступ к файлу: он остаётся основным после перезапуска и обновлений, а все изменения сохраняются в него автоматически.
- При запуске берётся самая свежая копия (например, если файл обновился с другого устройства).
- Если доступ к файлу пропал (файл удалён/перемещён), на главном экране появится предупреждение с кнопкой «Выбрать».
- Данные из `Documents/BJU/bju-data.json` старых версий подхватываются автоматически при первом запуске.

## Интерфейс (редизайн 2026)
Основа — нативное Android-приложение: зоны касания не меньше 44–48 dp, системные виброотклики, «Назад» и жесты Android, своя цифровая клавиатура.

**Главный экран.** Шапка с датой (касание — календарь, «К сегодня» под датой); когда записи прокручены под неё, под датой появляется линия (`src/js/06b-nav-edge.js`). Итог дня: съедено и «осталось» в одной строке, полоса калорий из вклада Б / Ж / У (перебор — красная обводка), три столбца Б / Ж / У («съедено / норма», полоска, «ещё N г»). Под итогом — чипы «Вес» и «В среднем за 7 дн.» (средние калории в день; если чип один в строке — и все три: Б · Ж · У). Приёмы пищи — карточки; записи — строки через линию: название, «60 г · Б · Ж · У» (буквы — цветами нутриентов), ккал, «×». **Изменить запись — двойным касанием** (одиночный свайп листает дни, поэтому изменение не срабатывает от случайного касания). Заголовок приёма — значок (восход, солнце, луна) и крупное название с суммой; от записей он отделён отступом, а не линией. Перекус — вторичная категория внутри карточки своего приёма: с записями — вставленным блоком со скруглением на своей подложке, со значком-яблоком, подписью прописными («ПЕРЕКУС 1») и «＋» без заливки; пустой — ссылкой «＋ Перекус N» (или по двойному касанию названия приёма).

**Нижняя панель** всегда у нижнего края: Календарь, Продукты, **＋**, Статистика, Ещё. Касание «＋» настраивается (Ещё › Главный экран › Кнопка «＋» в панели): приём пищи по времени (по умолчанию), новый продукт, новое блюдо, вес (если вес отслеживается) или скрыть кнопку. Значок меняется под действие. Потянуть вверх от панели, в том числе от «＋», — жест «Потянуть вверх».

**Нижний лист** прижат к низу и по высоте равен содержимому (список продуктов — всегда на всю высоту, чтобы не «прыгать» при поиске). Шапка: «‹ назад» (если «Назад» ведёт на шаг внутри листа), заголовок с подписью, «✕». Кнопки действия — внизу листа, у нижнего края. Смена экрана: содержимое меняется на месте (непрозрачный снимок старого экрана гаснет поверх нового за 0,11 с; сам новый экран — шапка, содержимое, низ — никогда не анимируется и не бывает прозрачным; ничего не едет вбок), плавно переезжает только верхний край листа к новой высоте (`sv()` / `svPlay()` в `src/js/12-sheet.js`). Если на том же экране меняется высота (подсказка жеста появилась или ушла, другой месяц в календаре), край листа и строки едут вместе, ушедший блок гаснет (`shResize()`). Все переходы листа — только `transform` и `opacity` (их рисует видеокарта, движение ровное даже пока приложение строит новый экран); край, который «срезает» старый экран, сделан встречным сдвигом рамки и копии, без анимации `clip-path`. Касание кнопок закреплённых панелей (нижняя панель, шапка, низ листа) не теряется, даже если Android потратил его на остановку прокрутки по инерции (`src/js/04c-tap.js`).

**Своя клавиатура** (`src/js/05b-input.js`, стили `src/css/06-keypad.css`) — для всех числовых полей: количество, вес, норма, Б / Ж / У продукта, граммы единицы, вес блюда. Поля с `inputmode="none"`: Android для них свою клавиатуру не открывает. Панель всегда у нижнего края, одной высоты (кнопка действия + 12 клавиш). Режим замены (первая цифра заменяет значение), одна запятая, не больше 2 знаков после неё и 4 до, удержание ⌫ — стереть всё; цифры с физической клавиатуры работают. В форме продукта и норме кнопка «Далее · Жиры» ведёт по полям, на последнем — «Сохранить». Текстовые поля (поиск, названия, код цвета) — с системной клавиатурой; видна только одна из двух: в APK своя панель уходит, когда системная начала подниматься.

**Ещё** — все настройки одной страницей: Норма; Данные (файл данных; там же импорт продуктов); Оформление (тема, цвет акцента и «Свой цвет», оттенок фона); Главный экран (кнопка «＋», карточка дня, кнопки «Новый продукт» / «Новое блюдо» — сверху (по умолчанию) или снизу, пустые перекусы, отслеживать вес); Добавление («Запоминать единицу»: продукт открывается в той же мере, что в прошлый раз — граммы, шт, банка, долька…; по умолчанию включено); Жесты (потянуть вниз, потянуть вверх, длина свайпа; подсказка-анимация показывается на экране жеста, если он не выключен); Отклик (вибрация). Выбор из нескольких вариантов — экран со списком и галочкой.

**Вибрация** (Ещё › Отклик): общий выключатель, сила (лёгкая / обычная / сильная) и семь случаев — клавиатура, добавление и сохранение, удаление и отмена, листание дней и месяцев, жесты «потянуть» и смахивание листа, переключатели, ошибки ввода. В APK — системные отклики Android (метод `feedback` в `BjuNativePlugin`), если система их не выполнила — обычная вибрация. Старое «Кроме дней» переносится автоматически.

**Жесты.** Свайп влево / вправо — соседний день (не начинается в 24 dp у краёв экрана: там жест «Назад» Android). Решение и темп — по скорости пальца (`dayCommit()` в `src/js/21-pull.js`, `hvel()` в `18-day-drag.js`): дотянули до порога, быстро махнули (от 18 px) — листается; махнули обратно в конце жеста — отмена. Уход дня продолжает движение пальца: быстрый взмах — 56–90 мс и дальше по инерции, появление нового дня — 150–230 мс; новый день показывается сразу по истечении ухода, серия взмахов не теряется (`src/js/15-day-slide.js`). Потянуть вниз в начале дня — календарь / к сегодня. Потянуть вверх — от нижней панели в любом месте списка и в конце дня (оба способа сразу). Внутри листа горизонтальный взмах листает месяцы календаря и статистики и вкладки «Все / Продукты / Блюда»: содержимое идёт за пальцем, срабатывает короткий быстрый взмах (от 24 px) или сдвиг на четверть ширины (`src/js/14b-hswipe.js`); «Длина свайпа» действует только на главном экране (дни, «потянуть») и на смахивание листа. Смахнуть лист вниз — закрыть (на своей клавиатуре не срабатывает); сдвиг листа пальцем снимается при каждом открытии и при оборванном касании (`shDragReset()` в `src/js/22-sheet-drag.js`) — иначе после смахивания и быстрого открытия другого окна лист оставался за краем экрана. Системный «Назад»: диалог → шаг в листе → закрыть лист → закрыть карточку дня → **к сегодняшнему дню** → свернуть приложение.

**Календарь**: строк столько, сколько недель в месяце; заголовок «Октябрь 2026 ⌄» — кнопка выбора месяца и года; калории под днём цветом — в норме ±10 % (зелёный), перебор (красный), недобор (жёлтый), внизу — счётчики месяца. **Статистика за месяц**: средний день (с долями калорий Б / Ж / У), дни с записями, лучшая серия, в норме / перебор / недобор, калории по дням, вес, БЖУ по дням в % нормы, «Чаще всего»; месяц — стрелками в шапке или свайпом.

**Карточка дня** — сводка для скриншота. Открывается тройным касанием по итогу дня (по умолчанию) или строкой «Карточка дня ›» внизу итога (Ещё › Главный экран › Карточка дня); закрыть — тем же тройным касанием, «Назад» или ✕. Свайп вверх / вниз — компактный / подробный вид.

**Стиль.** Акцент по умолчанию — индиго (не совпадает с цветами Б / Ж / У). Глубина без рамок: фон → карточка → блок. Палитра считается в OKLCH (`palette()` в `src/js/19-theme.js`): светлота каждой ступени задана, от акцента берутся оттенок и небольшая насыщенность (тёплые — вдвое слабее), поэтому на любом цвете тёмная тема — графит в тон, без коричневого; клавиатура, диалог и уведомление — тоже в тон. Тёмная тема — светлый графит (фон `#1e2126`, карточка `#282b31` для индиго), подписи не ниже 4,5 : 1 (проверяется тестом на 10 цветах в обеих темах). Уведомление (тост): в светлой теме — белое, в тёмной — на ступень светлее карточек; «Отменить» — цветом акцента. После добавления в тосте видно количество: «Завтрак: Банан · 120 г · 118 ккал». Единые размеры и цвета — в `src/css/00-base.css` и `01-palette.css`. Смена темы, цвета акцента и оттенка фона — лист с настройками плавно перетекает в новые цвета за 0,22 с, главный экран под затемнением меняется сразу и целиком (`themeFade()` в `src/js/05a-motion.js`, правило `html.thx` в `00-base.css`); экран всё время отвечает на касания, переключать можно быстро подряд. Цвета Б / Ж / У и состояний для текста — отдельные переменные `--pt --ft --ct --okt --wrt --dgt` (сдвинуты к цвету текста темы, контраст не ниже 4,5 : 1), мелкий текст на заливке акцентом — `--ons`. Открытие карточки дня — растворением через View Transitions (`vtx()`). Вид главного экрана (перекусы, вес, строка «Карточка дня») меняется плавным сжатием и раскрытием блоков (`mainMorph()`). Темп анимаций — короткий, с быстрым стартом и мягкой остановкой (`MO` и `--t1…--t3`, `--ease`). При системной настройке «Уменьшить движение» анимации выключены.

## Импорт продуктов из файла
«Файл данных» → группа «Импорт» → «Добавить продукты из файла»: из чужого файла (например, файла другого человека) берутся только продукты и блюда, дневник и настройки не меняются (`src/js/28-merge.js`). Перед добавлением открывается экран «Импорт продуктов» со сводкой и решениями; пока не нажата кнопка внизу («Добавить N · обновить M»), список не меняется:
1. **новые** — у вас такого нет; отмечены галочками, ненужные можно снять («Снять все / Выбрать все»);
2. **отличаются БЖУ** — то же название, другие числа: выбор «Мои» (по умолчанию) или «Из файла»;
3. **похожие** — одно название входит в другое (или большая часть слов общая) и БЖУ близкое: её «Яйцо» и ваше «Яйцо (варёное)». Для каждой пары — ваш самый близкий по БЖУ и выбор «Разные» (по умолчанию — добавится отдельно) или «Это одно» (к вашему добавятся меры из файла);
4. **уже есть** — то же название и те же числа: пропускаются, к вашему добавляются недостающие меры (банка, штука…).

Одинаковыми считаются названия с тем же набором слов: регистр, «ё», пробелы, знаки и порядок слов не важны («Грудка куриная» = «Куриная грудка»). Разные числа в названии («Молоко 2,5%» и «Молоко 3,2%»), продукт и блюдо — всегда разные; повторы внутри файла учитываются один раз. Если решать нечего, экран не открывается. В тосте — сколько добавлено, обновлено и новых мер; «Отменить» возвращает прежний список.

## Избранное и недавние
В списке продуктов у каждого есть звёздочка. При добавлении без поиска список делится на разделы: **Избранное**, **Недавние** (последние добавленные, до 8) и **Все продукты** (по частоте). При поиске избранные идут первыми. Блюда отмечены значком-миской и подписью «Блюдо»; в «Продуктах», если есть хотя бы одно блюдо, сверху есть фильтр «Все / Продукты / Блюда».

## Автотесты
`npm run test:all` — сборка и все тесты; `npm test` — только тесты по уже собранной `www/`. Проверяются: добавление и удаление записей, своя клавиатура (ввод, «Далее», одна клавиатура за раз), норма, свайп дней (и край экрана), календарь (три состояния дня), смахивание листа, «Назад» (в том числе к сегодня), листы у нижнего края, «Ещё» и экраны выбора, кнопка «＋», вибрация и её перенос, нижняя панель, избранное и недавние, блюда, вес, статистика, карточка дня (оба режима), формат файла и понятные ошибки, восстановление повреждённых данных, основной файл в APK (на моке нативной части), виджет (обе палитры, «＋» как в панели) и ярлыки, переходы листа без пустых кадров, взмахи внутри листа, импорт с конфликтами, «Запоминать единицу», контраст палитры на 10 цветах в обеих темах, контраст цветных подписей на экранах, нажатия панели без «click», случайные быстрые переходы между экранами (`tests/fuzz.test.mjs`: после каждой серии лист должен прийти в целое состояние — шапка видна и не закрыта, слои убраны), подложка перекуса и линия под шапкой в обеих темах, ресурсы иконки, отложенная копия данных в памяти браузера.
На GitHub тесты запускаются перед сборкой APK: если хоть один упал, APK не собирается и релиз не создаётся (ошибка видна в журнале шага **Run tests**). Локально нужен Chromium: `npx playwright install chromium` (или путь в `CHROMIUM_PATH`).

## Виджет и быстрые действия
- **Виджет** «БЖУ за сегодня» (долгое нажатие на рабочем столе → Виджеты), размер от 1×1 до 4×2 (если лаунчер позволяет растянуть выше — увеличенные раскладки). Раскладки генерирует `scripts/widget-layouts.py`, рисует `BjuWidget.java`. В разметке — только классы, которые умеет показывать RemoteViews (FrameLayout, LinearLayout, TextView, ImageView, ProgressBar…; распорки — пустые FrameLayout, простой `<View>` давал «Не удаётся загрузить виджет», это проверяет тест); если сборка вида упала, показывается простая раскладка 1×1: 1×1 — кольцо калорий с остатком на квадратной плашке; 1×2 — кольцо и под ним Б / Ж / У строками с полосками; 1×3 и выше (от 230 dp высоты) — то же, под кольцом подпись «осталось · из 2920», строки крупнее. В узких высоких раскладках кольцо стоит в слоте с весом (при нехватке места уменьшается, строки не обрезаются и при крупном шрифте), а запас высоты делят распорки между блоками — отступы растут равномерно, а не пустыми полосами сверху и снизу; 2×1 — слева остаток калорий, справа Б / Ж / У столбиком; 3×1 и 4×1 — крупный остаток («2107» / «+9021 перебор») и колонки Б, Ж, У со «съедено» и полосками (на 4×1 ещё «＋»); 2×2 — кольцо и Б / Ж / У; 3×2 и 4×2 — «Съедено X из Y», «＋», кольцо и строки «Белки 162 / 200» (крупные раскладки — только на полную ширину, в 3 колонки — средняя). Граммы — целые, названия не обрезаются, числа подстраиваются под место (`autoSizeTextType`, Android 8+). В превью списка виджетов — «964 осталось» в кольце и «＋» цветом акцента. Кольцо рисуется картинкой: размер числа считается от свободного места внутри (≈27 % диаметра с подписью, ≈42 % без неё — в малых кольцах 1×1 и 1×2 число крупное; длинное число уменьшается, чтобы не касаться линии), подпись «осталось» — только если помещается; при переборе — «+N» и красный цвет. Цвета — из приложения: оно передаёт светлую и тёмную палитры; при теме «Как в системе» на Android 12+ виджет переключается вместе с телефоном сам, на старых — при обновлении. Скругление на Android 12+ — системное. **«＋» на виджете делает то же, что «＋» в панели** (настройка «Кнопка «＋» в панели»; если кнопка скрыта — приём пищи по времени), ссылка `bju://fab`. В полночь виджет сам обновляется и показывает новый пустой день (будильник без точного времени — система может сдвинуть на пару минут).
- **Быстрые действия** — долгое нажатие на иконку приложения: Завтрак, Обед, Ужин, Перекус (ближайший по времени) и **Вес** (только если отслеживание веса включено; если выключить, закреплённый ярлык «Вес» становится неактивным). Сразу открывается добавление в выбранный приём пищи или ввод веса на сегодня.
- Оба механизма открывают ссылку `bju://add?m=…` (`0`–`5` — номер приёма пищи, `snack` — ближайший перекус, `auto` — по времени); ярлык веса — `bju://weight`.

## Формат файла данных (версия 3)
Файл — обычный JSON с отступами, его можно править вручную в любом текстовом редакторе.

```json
{
  "format": "bju-diary",
  "version": 3,
  "savedAt": "2026-10-16T11:00:00.000Z",
  "goals": { "protein": 120, "fat": 70, "carbs": 250 },
  "products": [
    { "name": "Творог 5%", "per100g": { "protein": 17, "fat": 5, "carbs": 1.8 }, "favorite": true },
    { "name": "Куриная грудка (сырая)", "per100g": { "protein": 23.6, "fat": 1.9, "carbs": 0.4 },
      "units": [ { "name": "шт", "grams": 180 } ] },
    { "name": "Салат", "per100g": { "protein": 2, "fat": 5, "carbs": 6 },
      "dish": { "cookedWeight": 300, "ingredients": [
        { "name": "Огурец", "grams": 200, "protein": 1.6, "fat": 0.2, "carbs": 5 } ] } }
  ],
  "diary": {
    "2026-10-16": {
      "breakfast": [ { "name": "Яблоко", "grams": 55, "protein": 0.2, "fat": 0.2, "carbs": 5.4,
                       "unit": { "name": "шт", "count": 1 } } ],
      "lunch": [ { "name": "Рис", "grams": 100, "protein": 7, "fat": 1, "carbs": 74 } ]
    }
  },
  "weight": { "2026-10-16": 72.4 },
  "settings": { "theme": "dark", "accentColor": "#22a06b", "pullUpAction": "meal",
                "pullDownAction": "calendar", "vibration": "on", "swipeLength": "medium",
                "backgroundTint": "soft", "weightTracking": "on",
                "newButtons": "top", "dayCard": "tripleTap", "fabAction": "meal", "rememberUnit": "on" },
  "stats": { "useCount": { "Рис": 3 }, "lastGrams": { "Рис": 100 }, "lastUnit": { "Банан": { "unit": "шт", "amount": 2 }, "Рис": { "unit": null } }, "recent": [ "Рис" ] }
}
```

| Раздел | Что это |
|---|---|
| `goals` | Норма на день, граммы белков / жиров / углеводов (калории считаются: Б×4 + Ж×9 + У×4) |
| `products` | Список продуктов. `per100g` — БЖУ на 100 г (незаполненное считается 0). `units` — свои единицы («шт» = 180 г), необязательно. `dish` — только у блюд: вес готового блюда и ингредиенты. `favorite: true` — в избранном |
| `diary` | Дневник по датам `ГГГГ-ММ-ДД`. Приёмы пищи: `breakfast`, `snack1`, `lunch`, `snack2`, `dinner`, `snack3` (пустые можно не писать). В записи — масса порции `grams` и БЖУ **этой порции**; `unit` — если добавляли в штуках |
| `weight` | Вес по дням, кг (одна запись на день) |
| `settings` | `theme`: auto/light/dark; `accentColor`: цвет `#rrggbb`; `pullUpAction`: meal/product/stats/weight/off; `pullDownAction`: calendar/today/off; `vibration`: on/exceptDays/off; `swipeLength`: short/medium/long; `backgroundTint`: off/soft/strong — примесь акцентного цвета в фон; `weightTracking`: on/off; `bottomBar`: page/fixed; `newButtons`: top/bottom; `snacks`: row/doubleTap; `rememberUnit`: on/off — «Запоминать единицу»; `productImport`, `gestureHints`, `pullUpFrom` — больше не используются (импорт всегда в «Файле», подсказки показываются сами, тянуть вверх можно и от панели, и в конце списка), сохраняются без изменений; `dayCard`: tripleTap/row — как открывать карточку дня; `fabAction`: meal/product/dish/weight/hidden — кнопка «＋»; `vibrationStrength`: light/normal/strong; `vibrationEvents`: `{ kb, save, del, days, pull, ui, err }` — где вибрировать (true/false). `bottomBar` больше не используется (панель всегда закреплена), но сохраняется без изменений|
| `stats` | Служебное: сколько раз продукт добавлялся (сортировка списка), последняя масса (подсказка), последняя единица (`lastUnit`: мера и количество, `unit: null` — граммы) и недавние продукты. Можно удалить |

Если при открытии файла что-то не так, приложение покажет, где именно ошибка: например, «день 2026-10-01: неизвестный приём пищи «lanch»» или «продукт №5: нет названия». Файлы старого формата тоже открываются и при следующем сохранении записываются в новом.

## Локальная сборка
```bash
npm ci
npm run android:prepare   # иконки + веб-сборка + android/ + версия
cd android && ./gradlew assembleDebug
```
Папки `android/`, `www/`, `assets/` генерируются и в репозиторий не коммитятся.
